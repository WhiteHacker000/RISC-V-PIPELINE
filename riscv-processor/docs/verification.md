# Verification

Run `make test` from the repository root. Each listed testbench is compiled with Verilator and then executed; a compile or simulation failure stops the regression with a nonzero status.

| Area | Testbench |
|---|---|
| ALU | `alu_tb` |
| Register file | `register_file_tb` |
| Immediate generator | `immediate_generator_tb` |
| Instruction/data memories | `instruction_memory_tb`, `data_memory_tb` |
| Decoder/control | `main_decoder_tb`, `control_unit_tb` |
| PC and pipeline registers | `program_counter_tb`, `if_id_tb`, `id_ex_tb`, `ex_mem_tb`, `mem_wb_tb` |
| Forwarding and interlock | `forwarding_unit_tb`, `hazard_detection_unit_tb` |
| Integrated processor | `processor_tb`, `pipeline_corner_tb` |

The processor integration test checks RAW dependencies, write ordering and overlap, load-use stalling, and BEQ/BNE redirect/flush behavior. Counter assertions verify exact cycle/retirement/stall/flush counts for independent, dependent, load-use, branch, three-ADDI, and 64-instruction arithmetic benchmarks. They verify that the injected load-use bubble and flushed branch-path instructions do not retire, and that WB-completion equals retirement. The test writes measured counters to `simulation/performance.csv`; `verification/performance.py` validates that output and generates the CPI/IPC results table and graph. A successful compile alone is not a pass; the simulation and CSV validation must both complete successfully. Waveforms are generated under `riscv-processor/simulation/` by traced testbenches.

Useful checks are `make lint` and `make synth`. Yosys `check` reports structural issues; this is not a technology-mapped implementation or timing-closure result. The flow currently uses `-Wno-fatal` for testbench compilation because some existing modules/testbenches emit nonfatal style warnings.

## Corner-case integration bench (`pipeline_corner_tb`)

`testbench/pipeline_corner_tb.sv` runs seven `riscv_top` instances in parallel, one program per verification target. The programs are `programs/verif_*.hex`, and each line carries its assembly as a comment. They are generated by `verification/gen_corner_programs.py`, whose encoder was cross-checked against the existing hand-written `processor_*.hex` words. The bench does not touch the performance calculation. It only reads the existing counters and compares them with counts it measures independently.

A `pipeline_invariant_monitor` is attached to every instance. On each falling clock edge it checks these invariants:

- After a taken branch, IF/ID holds the canonical NOP and ID/EX is a bubble (no reg/mem write, mem read or branch).
- After a load-use stall, PC and IF/ID are unchanged and ID/EX is a bubble.
- `forward_a`/`forward_b` never select a source while the corresponding `idex_rs1`/`idex_rs2` is x0.
- No register write (rd ≠ x0) and no memory write originates from a slot the validity tracker marks invalid.
- Its own count of stall and flush events must equal `perf_stall_cycles` and `perf_branch_flushes`.

### Initial-state robustness

The register file has no reset; this is architecturally allowed, since only x0 is defined. Verilator zero-initialises state by default, which can hide dependence on initial values. Both integration benches were also run with `--x-initial unique --x-assign unique +verilator+rand+reset+2`:

- `pipeline_corner_tb`: **pass** on 8 seeds. Registers that are never written are compared against their post-reset value, not against 0.
- `processor_tb`: **fails** on every seed tried (3). Its branch check expects never-written wrong-path registers x5/x6 to equal 0, which holds only under zero-initialisation. This is a testbench limitation, not an RTL defect. The existing assertion was left unchanged and should be resolved by its owner, for example by comparing against a post-reset snapshot.

## Findings and observations

### Final lint warning classification

The current `make lint` run exits 0 with eight nonfatal `-Wall` diagnostics:

| Diagnostic | Classification | Reason |
|---|---|---|
| `EOFNEWLINE` in `alu.sv` | Documentation/style issue | Missing final newline only. |
| `PINCONNECTEMPTY` for `alu_op` | Intentional design choice | `control_unit` exposes this unused intermediate output; the integrated top consumes `alu_control` directly. |
| `UNUSEDSIGNAL` for `exmem_branch_target`, `exmem_branch_taken`, `exmem_pc_plus4` | Unused signals | Payload outputs are carried by EX/MEM for observability/future extension, but are not consumed in this top. |
| `UNUSEDSIGNAL` for `load_use_stall` | Unused signal in synthesized top | Alias retained for testbench observability; interlock uses `stall_pc`/`stall_ifid`/`flush_idex`. |
| `UNUSEDSIGNAL` for immediate input bits `[19:12]` | Intentional design choice | I/S/B immediate reconstruction does not use those instruction fields. |
| `SYNCASYNCNET` for `rst_n` | Intentional design choice | PC reset is asynchronous; pipeline/counter reset is synchronous active-low, as documented and tested. |

No warning indicates a functional defect. The width-expansion warning found in
the first implementation of program validity was corrected before the final
lint run. No warnings are suppressed beyond the existing `-Wno-fatal` behavior.

No RTL functional defect was found. The RTL was not changed. Items to coordinate:

1. `processor_tb` depends on zero-initialised registers (see above).
2. SW treats rs2 (store data) as a load-use source. This costs a stall that MEM-stage forwarding could avoid. It is a correct but conservative design choice, and `u_lu` pins this behaviour (exactly 5 stalls).
3. `hazard_detection_unit` priority "redirect wins over load-use stall" cannot be reached in the integrated core: ID/EX cannot hold a load and a branch at the same time, so it is covered only by the unit bench.
4. Lint `SYNCASYNCNET`: `rst_n` drives both the asynchronous PC reset and the synchronous pipeline-register resets. This is documented in `architecture.md` and is behaviourally verified by R8.2–R8.5.
5. Unused or stale files: `rtl/stages/*.sv` is not part of the `make` RTL list and is not exercised. `testbench/pipeline_tb.sv` is an empty stub and is not in `make test`. `verification/reference_model.py` is empty. `programs/arithmetic.hex`, `branch.hex` and `memory.hex` hold binary strings (read as hex by `$readmemh`) with comments naming unsupported instructions, and no bench loads them.

## Not tested

These scenarios are **not** covered by any bench in `make test`:

- Unsupported or illegal instructions flowing through the integrated pipeline. Decode of unsupported encodings is covered at unit level only, in `control_unit_tb` and `main_decoder_tb`.
- Misaligned or out-of-range LW/SW, or branch targets inside the integrated core. Misaligned and out-of-range accesses are covered only in the memory unit benches.
- PC reaching the end of IMEM (`IMEM_DEPTH`), and PC wraparound.
- Reset *deassertion* coincident with a clock edge. All benches release reset between edges.
- A taken branch whose target instruction is itself a taken branch.
- A load-use stall and a taken branch asserted in the same cycle. This is unreachable in the integrated core (finding 3) and is covered only by the unit bench.
- Long or random programs. There is no random instruction generator and no ISS/reference-model comparison, because `reference_model.py` is empty.
- Code or functional coverage collection (`verilator --coverage`), formal or property checking, gate-level simulation and timing.
- Waveform-level manual review. All checks are self-checking assertions.
